## What It Does

A student brings their own Gemini API key and Cloudinary account. They sign up, create courses, upload typed PDFs, and the system does the rest:

1. **Upload a PDF** — the system analyzes it for page count, extracts text, detects scanned/camera-snapped documents, and stores it on Cloudinary.
2. **AI generates study materials** — using the student's own Gemini key, the system produces 15-40 flashcards and a 10-question multiple-choice test from the PDF content.
3. **Study** — flip through flashcards with keyboard controls (space to flip, arrows to navigate).
4. **Test yourself** — take the generated test, get instant scoring, and review past attempts.
5. **Track progress** — dashboard shows total courses, pages studied, flashcards created, average test score, and recent attempts.

The system enforces a **30-page cumulative budget per course** (to keep study focused), detects scanned PDFs that lack selectable text, and provides clear failure messages with retry support for transient errors.

### Request flow for PDF upload:

```
Student uploads PDF
        │
        ▼
  Parse multipart form data
        │
        ▼
  Analyze PDF (pdfjs-dist)
  ├─ Page count ─▶ Check against 30-page course budget
  └─ Extract text ─▶ 60,000 char max
        │
        ▼
  Upload to Cloudinary (raw PDF)
  └─ Store cloudinaryUrl + cloudinaryPublicId
        │
        ▼
  Return 202 immediately (material status: "uploaded")
        │
        ▼  (async, 650ms delay)
  Scanned PDF check
  └─ If < 100 chars/page → mark as "failed" (scanned_pdf), release page budget
        │
        ▼  (if text-based)
  Gemini generation
  ├─ 15-40 flashcards (JSON)
  └─ 10 multiple-choice questions (JSON)
        │
        ▼
  Save to MongoDB, mark material as "ready"
  OR mark as "failed" (generation_error / quota_exhausted)
```

## Getting Started (Local Development)

### Prerequisites

- **Node.js** 24+
- **pnpm** 12+ (enforced by preinstall script)
- **MongoDB Atlas** account (free tier works)
- **Cloudinary** account (free tier, API key with upload permissions)
- **Google AI Studio** account (free tier, Gemini API key)

### 1. Clone and install

```bash
git clone https://github.com/YOUR_USERNAME/Anki-Speed-Read.git
cd Anki-Speed-Read
pnpm install
```

### 2. Set up environment variables

```bash
cp .env.example .env
```

Then fill in `.env` with your credentials (see [Environment Variables](#environment-variables) below).

### 3. Start the development servers

```bash
# Terminal 1 — API server (port 3000)
pnpm --filter @workspace/api-server run dev

# Terminal 2 — Frontend (port 5173)
pnpm --filter @workspace/anki-speed-read run dev
```

The frontend runs on `http://localhost:5173` and proxies API requests to `http://localhost:3000`.

### 4. Open the app

Visit `http://localhost:5173` in your browser. Sign up with your name, email, password, and Gemini API key.

Create a `.env` file at the repository root (gitignored). All variables are required.

| `CLOUDINARY_API_KEY` | Cloudinary Dashboard → Settings → Access Keys | API key with **upload** permissions |
| `CLOUDINARY_API_SECRET` | Cloudinary Dashboard → Settings → Access Keys | Corresponding API secret |
| `PORT` | (optional, default `3000`) | Server port |

### Generating secure keys

```bash

# ENCRYPTION_KEY
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

All endpoints are prefixed with `/api`. Authentication uses `Authorization: Bearer <JWT>` headers.

### Health

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/healthz` | No | Returns `{ "status": "ok" }` |

### Authentication

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/signup` | No | Create account (requires `fullName`, `email`, `password`, `geminiApiKey`) |
| POST | `/auth/login` | No | Log in (returns JWT + student profile) |
| GET | `/auth/me` | Yes | Get current student profile |
| PATCH | `/auth/gemini-key` | Yes | Validate and update stored Gemini key |

### Courses

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/courses` | Yes | List student's courses with summary stats |
| POST | `/courses` | Yes | Create course (body: `{ title, description? }`) |
| GET | `/courses/:courseId` | Yes | Get course detail with materials list |
| PATCH | `/courses/:courseId` | Yes | Update course title/description |
| DELETE | `/courses/:courseId` | Yes | Delete course and all its materials |

### Materials

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/courses/:courseId/materials` | Yes | List materials in a course |
| POST | `/courses/:courseId/materials` | Yes | Upload PDF (multipart/form-data, field: `file`). Rate-limited: 10 per minute. |
| GET | `/materials/:materialId` | Yes | Get material status and metadata |
| DELETE | `/materials/:materialId` | Yes | Delete material (blocked while processing) |
| POST | `/materials/:materialId/retry` | Yes | Retry generation for `generation_error` or `quota_exhausted` failures |

### Study

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/courses/:courseId/flashcards` | Yes | Get merged flashcard deck for a course |
| GET | `/materials/:materialId/test` | Yes | Get the generated test (10 questions) |
| POST | `/tests/:testId/attempts` | Yes | Submit answers (body: `{ answers: number[] }`), returns score |
| GET | `/students/me/attempts` | Yes | List recent test attempts |
| GET | `/students/me/summary` | Yes | Dashboard summary (courses, pages, cards, avg score, recent attempts) |

### Error responses

All error responses follow the shape `{ "error": "<human-readable message>" }` with appropriate HTTP status codes:

| Status | When |
|--------|------|
| 400 | Bad input (missing fields, page limit exceeded, invalid PDF, scanned PDF) |
| 401 | Missing or invalid JWT, wrong password |
| 404 | Course, material, or test not found |
| 409 | Material still processing (can't delete yet) |
| 429 | Upload rate limit exceeded (10/min) |
| 502 | Cloudinary upload failure |

## How the Upload Pipeline Works

### Step 1: Multipart parsing and validation

The uploaded file is parsed from the raw multipart body. Only `application/pdf` files are accepted.

### Step 2: PDF analysis (pdfjs-dist)

The PDF is loaded with `pdfjs-dist` (legacy ESM build) to extract:
- **Page count** — used to enforce the 30-page course budget
- **Full text** — extracted from the text layer of the PDF

If the PDF cannot be read at all, the user gets: *"We could not read this PDF. Please upload a valid, uncorrupted file."*

### Step 3: Page budget pre-check

Before any external calls, the system checks `course.totalPageCount + pageCount > 30`. If the upload would exceed the budget, it returns a 400 with a message showing exactly how many pages are used and how many the file would add.

### Step 4: Cloudinary upload

The PDF buffer is uploaded to Cloudinary as a raw asset under the `asr/` prefix. If Cloudinary fails, the user gets: *"We could not store this PDF right now. Please try again in a moment."*

### Step 5: Material created (202 response)

The material is saved with status `"uploaded"` and the response is returned immediately. The async processing continues in the background.

### Step 6: Async scanned-PDF check (650ms delay)

The system checks `extractedCharCount / pageCount < 100`. If the PDF has fewer than 100 characters per page, it is classified as a scanned/camera-snapped document. The material is marked as `"failed"` with `failureType: "scanned_pdf"` and the page budget is released.

### Step 7: Gemini generation

For text-based PDFs, the system calls Gemini 2.0 Flash twice:
1. **Flashcards** — 15-40 cards depending on content density
2. **Test** — exactly 10 multiple-choice questions with 4 options each

On success, the material is marked `"ready"`. On failure:
- **`generation_error`** — can be retried
- **`quota_exhausted`** — can be retried (after topping up the Gemini key)
- The page budget is released on failure

## How Gemini Generation Works

Each student provides their own Gemini API key at signup. The key is:
1. **Validated** live against Google's API at signup and on every key update
2. **Encrypted at rest** with AES-256-GCM before storage in MongoDB
3. **Decrypted and used** only during generation, then discarded from memory

### Generation prompts

**Flashcards prompt:**
> Generate study flashcards from the text below. Return JSON only: `[{"front":"string","back":"string"}]`. Produce 15-40 cards. Front should be concise (question or concept), back should be complete (answer or definition). Include the source filename and full source text.

**Test prompt:**
> Generate a test from the text below. Return JSON only: `[{"question":"string","options":["A","B","C","D"],"correctIndex":0,"explanation":"string"}]`. Exactly 10 questions, 4 options each, one correct answer, one-sentence explanation. Include the source filename and full source text.

### Key validation (`checkGeminiKey`)

At signup and key-update, the system pings `generativelanguage.googleapis.com/v1beta/models` with the provided key:
- **400/401/403** → key is definitively invalid → signup rejected with: *"That Gemini API key looks invalid. Double-check it at Google AI Studio (aistudio.google.com/apikey)."*
- **Network errors or timeouts** → key might be valid but unreachable → **tolerated** (signup proceeds)
- **200** → key is valid

## Security

| Concern | Implementation |
|---------|---------------|
| **Password storage** | bcryptjs with 12 salt rounds |
| **Session tokens** | JWT signed with `JWT_SECRET`, 14-day expiry |
| **Gemini key encryption** | AES-256-GCM with random IV, unique per student. Keys are never returned to the client. |
| **CORS** | Configurable origin whitelist |
| **Upload rate limiting** | 10 uploads per minute per IP (express-rate-limit) |
| **Input validation** | All request bodies validated; field types checked before use |
| **PDF size control** | 30-page cap per course; 60,000 char text truncation |
| **Supply-chain defense** | `minimumReleaseAge: 1440` in pnpm config (1-day delay before any npm package version can be installed) |
| **Environment secrets** | `.env` file is gitignored; `.env.example` provides a template |

## Deployment

### Replit (Recommended)

This project is configured for Replit's monorepo deployment system via `.replit-artifact/artifact.toml` files.

**Setup:**

1. Fork/import this repo into Replit
2. Go to **Settings → Secrets** and add all required environment variables:
   - `MONGODB_URI` — your MongoDB Atlas connection string
   - `JWT_SECRET` — a random 32+ hex character string
   - `ENCRYPTION_KEY` — a random 32+ hex character string
   - `CLOUDINARY_CLOUD_NAME` — your Cloudinary cloud name
   - `CLOUDINARY_API_KEY` — your Cloudinary API key (must have upload permissions)
   - `CLOUDINARY_API_SECRET` — your Cloudinary API secret
3. Click **Deploy**

The deployment builds both the API server (esbuild ESM bundle) and frontend (Vite), then runs them as separate artifacts:
- **API server** on port 8080 (`node dist/index.mjs`)
- **Frontend** as a static site on port 22318 (serves `dist/public/`)

### Manual Deployment

```bash
# Build everything
pnpm run build

# Or build individual packages
pnpm --filter @workspace/api-server run build    # → dist/index.mjs
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/anki-speed-read run build  # → dist/public/

# Run the API server
PORT=3000 node artifacts/api-server/dist/index.mjs
```

## Known Limitations

- **Per-student Gemini key:** Each student must bring their own Gemini API key. There is no shared/server-level key.
- **30-page course budget:** Enforced cumulatively. Removing a material releases its page count back.
- **Text-based PDFs only:** Scanned/camera-snapped PDFs are rejected with a clear message. OCR is not currently supported.
- **No real-time updates:** Material status is polled every 1.2 seconds on the frontend (not WebSocket-based).
- **60,000 character truncation:** Long PDFs have their text truncated before being sent to Gemini.
- **Gemini generates once:** Flashcards and tests are generated once per material. Retry only works for `generation_error` and `quota_exhausted` failures.
